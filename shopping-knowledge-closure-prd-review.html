총평 — 일정 설계(일요일 종료로 주간 집계 사이클 보존, 프론트/배치 종료 시점 분리, 절삭 예시 표, FAQ 선제 작성)는 방향이 정확합니다. 다만 ① 추천 점수의 주차 귀속 로직 미검증(C-2), ② 차감 로직 종료 시점과 어뷰징 대응의 모순(C-3), ③ 마지막 집계 주간 전체가 추석 연휴와 겹치는 일정 리스크(H-5, 확정)가 해소되기 전에는 개발요청서로 전환할 수 없습니다.

Critical — 이대로 진행 시 사고

공지 발행(8/24) 또는 개발 착수 전 반드시 해결. 미해결 시 대외 오안내 또는 지급 사고로 직결됩니다.

C-1
공지 원문의 "구매가이드 종료" 표기 — 존치 계획과 충돌§6-1 공지 원문
문제
공지 원문 종료 대상 : "쇼핑지식 (구매가이드 / 사용기 / 누리라운지 / 쇼핑Q&A)"

구매가이드는 플랫폼 전환 후 존치되는 서비스임. 이대로 공지가 나가면 "구매가이드도 없어진다"는 대외 오안내가 됨.

수정 제안

구매가이드 커뮤니티 기능(댓글·추천) 종료는 확정. 이에 따라 종료 대상을 "사용기 / 누리라운지 / 쇼핑Q&A"로 한정하고, 구매가이드는 별도 줄로 분리하여 "구매가이드는 계속 제공되며, 댓글·추천 등 커뮤니티 기능만 종료됩니다"로 명시. 화면 처리 섹션의 댓글·추천 적용 영역(구매가이드 포함)과 정합 유지.

C-2
추천 최종 집계분(9/28 08:00)의 "주차 귀속" 로직 미검증§5-2 추천 활동점수 처리
배경

추천 점수는 글·댓글(즉시 적립)과 달리 익일 08:00 배치로 적립되어, 발생과 적립 사이 최대 하루의 시차가 있음. 일요일 추천 건은 항상 다음 주 월요일에 적립 처리되므로, 발생 주차와 적립 처리일의 주차가 어긋나는 유일한 케이스.

문제

PRD는 9/27(일) 발생 추천이 마지막 주차(9/21~27)에 "포함"된다고 선언만 하고 있음. 이는 현행 배치가 어느 기준으로 귀속하는지에 따라 성립 여부가 갈림:

패턴 A — 발생일 기준 귀속

{ 점수: 5P, 귀속일: 9/27(일) }

주간 집계가 "귀속일 9/21~9/27"을 합산 → 마지막 주차에 정상 포함 → 10/1 지급 ✓ 별도 조치 불필요.

패턴 B — 처리일(적립일) 기준 귀속

{ 점수: 5P, 적립일: 9/28(월) }

9/28~10/4 주차 점수로 잡힘 → 해당 주차의 지급일(10/8)은 오지 않음(10/2 배치 종료) → 9/27 하루치 추천 점수 전체 증발 ✗

패턴 B라도 평상시엔 다음 주 지급에 이월되므로 문제가 드러나지 않음. 서비스 종료가 "다음 주"를 없애는 순간에만 버그가 되는 구조라 개발·QA 모두 지나치기 쉬움. 게다가 공지 원문·FAQ에 "9월 27일에 받은 추천도 반영되나요? → 네"라고 이미 대외 약속이 박혀 있어, 누락 시 단순 CS가 아니라 공지 위반 → 전건 수동 보상 + 정정 공지까지 감.

액션 (순서대로)
  1. 개발 확인 요청 (문안 그대로 사용 가능): "추천 점수 적립 배치가 점수를 기록할 때, 주간 집계의 귀속 기준이 되는 날짜 컬럼에 추천 발생일이 들어가나요, 배치 실행일이 들어가나요? 일요일 발생 추천 건이 어느 주차 지급분에 포함되는지 확인 부탁드립니다."
  2. 패턴 A 확인 시 — PRD §5-2에 "현행 배치는 발생일 기준 귀속으로 확인됨 (확인일자 / 확인자)" 1줄 명기 후 종결.
  3. 패턴 B 확인 시 — 처리 방안 택1 확정 후 명기:
    · B-1 집계 범위 확장: 9/28 확정 배치의 집계 조건을 9/21~9/27 → 9/21~9/28 08:30으로 한시 변경해 월요일 적립분 흡수. 글·댓글은 9/27 23:59 차단이므로 이 구간엔 추천 적립분만 존재한다는 전제를 QA 항목화.
    · B-2 수동 합산: 9/28 배치 결과를 추출해 지급 대상 산출 시 수동 가산. 코드 무수정이나 휴먼 에러 리스크 — 담당자(김민지) 지정 및 더블체크 절차 필수.
  4. QA 체크리스트 추가: 스테이지에서 일요일 시각으로 추천 발생 → 월요일 배치 실행 → 직전 주차 지급 대상 금액에 포함되는지 검증. 최종 지급 정합성 QA 1순위.
C-3
점수 차감 로직 9/27 비활성화 ↔ 어뷰징 대응 수단 모순§4 배치 종료 순서 주의
문제
"활동점수 차감 로직(게시글 삭제 시)은 9/27 적립 종료와 동시에 비활성화하며…"

이 정의대로면 9/28~10/1 사이 운영자가 도배·광고글을 삭제해도 점수가 차감되지 않아, 어뷰징으로 적립된 점수가 그대로 e머니로 지급됨. 유의사항에는 "도배성 글은 적립이 제한될 수 있다"고 대외 고지해 놓고 실행 수단이 없는 상태.

확정 제안

자동 차감은 9/27 비활성화 유지하되, 어드민 수동 차감 기능은 10/1 지급 배치 실행 직전까지 유지. "지급 완료된 e머니는 회수하지 않음" 원칙은 그대로 유지. §4 주의 문구와 §8에 반영.

C-4
종료 직전 포인트 파밍(어뷰징) 대응 절차 부재§5 상세 정책 전반
문제

현금성 리워드 종료 공지(D-34) 이후 마지막 주간에 어뷰징 스파이크가 발생하는 것은 정형화된 패턴. 특히 마지막 주간에는 "다음 주 제재"라는 억지력이 사라짐. 현재 PRD에는 검수·보류·제외에 대한 절차가 전무.

추가할 것
  • 운영 검수 기간 신설: 9/28(월)~9/30(수)을 지급 전 검수 기간으로 명시. 지급 대상자 산출 후 상위 적립자 N명(제안: 상위 50명 + 전주 대비 적립 3배 이상 급증자) 수동 검수.
  • 지급 보류/제외 판정 기준: 기존 도배·광고 정책 원용, 판정 시 해당 주차 적립분 차감(C-3의 수동 차감 경로 활용).
  • 검수 담당자 지정 및 판정 이력 기록 방식.
  • QA 항목: 등급별 일 한도(누리그린 1,000P / 누리패밀리 3,000P / 누리VIP 5,000P)가 마지막 주에도 정상 동작하는지 검증.
리스크

마지막 집계 주간이 추석 연휴(H-5)와 겹쳐 운영 모니터링 공백이 예상되므로, 검수 기간·담당 확정은 더욱 필수.

High — 개발 되물음 · QA 이슈 예상

개발요청서 전환 전 PRD에 확정값으로 반영 필요. 미반영 시 개발 왕복 또는 QA 단계 이슈로 회귀합니다.

H-1
적립 종료 컷오프 기준 미정의§4 ④ / §8

"9/27 23:59"만으로는 부족. 서버 시간 23:59:59 기준, 등록 API의 서버 도달 시각으로 판정임을 명시할 것 (클라이언트 시간 아님).

경계 케이스 확정

23:58 작성 시작 → 00:00 이후 등록 클릭 → 등록 실패 처리 + 알럿 문구 확정 제안: "쇼핑지식 서비스 종료로 글 등록이 마감되었습니다. 작성하신 내용은 저장되지 않으니 별도 보관해 주세요." 댓글·추천도 동일 원칙 적용.

H-2
기존 글 수정·삭제 허용 여부 누락 (읽기 전용 기간 9/28~10/15)§8

글쓰기 종료만 정의되어 있고 본인 글 삭제 가능 여부가 없음. 개인정보가 포함된 글의 삭제권은 열람 종료 전까지 열어둬야 함.

확정 제안

삭제는 10/15 열람 종료 전까지 허용, 수정은 9/27 이후 차단 (수정 허용 시 광고글 변조 리스크). 삭제 시 점수 차감은 C-3 결정에 따름(자동 차감 없음, 어뷰징 건만 수동 차감).

H-3
마이페이지 활동점수·등급·랭킹 화면 처리 통째로 누락§8
  • 활동점수 조회 화면: 적립 내역·전환 예정 점수 표시를 언제까지, 어떻게 노출하는지 미정.
  • 10/1 지급 후 남는 5P 미만 절삭 잔여분이 계속 표시되면 CS 유발 — 지급 완료 후 0P 처리 또는 "소멸" 표기 중 택1 확정 필요.
  • 활동랭킹 페이지: 종료 시점·처리 방식(페이지 제거 vs 동결 표시) 미정.
H-4
3차 안내 "푸시" 발송 스펙 부재§4 ③

발송 대상(전체 / 최근 90일 쇼핑지식 활동자 / 마케팅 수신 동의자 한정 — 정보성 vs 광고성 분류에 따라 법적 필수 여부 갈림), 발송 시각, 푸시 문구, 랜딩(공지 상세) 모두 미정. H-5와 연동하여 발송일 자체 재검토 필요.

H-5확정 이슈로 승격
마지막 집계 주간이 추석 연휴와 정면 충돌§4 종료 일정 전체
확인 결과 (08/18 조사)

2026년 추석 당일 9/25(금), 법정 연휴 9/24(목)~9/26(토), 일요일 9/27로 이어져 실질 9/24~9/27 4일 연휴. 대체공휴일 없음.

PRD 일정달력 현실영향

액션

① 3차 안내 발송일을 9/23(수, 연휴 전 마지막 영업일)로 앞당기는 안 검토. ② 연휴 기간 장애·어뷰징 대응 담당(당직) 지정. ③ 9/28 아침 배치 실행 결과 확인을 체크리스트 최상단에 배치.

H-6
10/2(금) 배치 종료가 무조건 실행이면 위험§4 ⑧

10/1 지급 배치가 실패·부분 실패할 경우 재시도 여지가 하루뿐이고, 직후가 개천절 연휴(10/3~10/5).

확정 제안

"10/1 지급 결과 대사(지급 대상자 수 = 실제 지급 건수, 총 지급 e머니 합계 일치) 완료 확인 후 배치 종료"로 조건부 전환. 대사 담당자 지정.

H-7
지급 누락 CS 대응 수단·기한 미정의

배치 종료 후 누락 건 발견 시 e머니 수동 지급 경로(어드민 기능 or e머니 운영 프로세스)와 유지 기한 필요. 제안: 최종 지급일 +30일(~10/31)까지 수동 지급 경로 유지, CS 접수 → 적립 이력 확인 → 수동 지급 프로세스와 담당 명시.

H-8
회원 등급 종료의 영향도 미분석§6-1 유의사항 / FAQ

누리그린/누리패밀리/누리VIP 등급이 쇼핑지식 외 다른 혜택·이벤트 응모 자격 등과 연동되어 있는지, "종료"가 데이터 삭제인지 표시 제거인지 미정.

확인 필요 — 등급 데이터를 참조하는 타 서비스·이벤트 유무 (개발 조회 요청)
H-9
공지 게시 전 법무 검토 절차 누락§6 / §6-1
문제

e머니 약관상 30일 전 공지 의무가 걸린 공지문으로, 문구 하나가 약관 위반 리스크로 직결됨. F-2(푸시 광고성 분류)·F-3(데이터 파기)·F-4(약관 개정 해당 여부)는 법무 확인 항목으로 잡혀 있는데 정작 공지 원문 자체의 법무 검토 절차가 없음. 검토가 늦어지면 게시일(8/24)이 밀리고, 30일 공지 의무 때문에 9/27 종료일까지 연쇄 지연되는 구조.
